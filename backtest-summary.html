CDV · 신규제안 모드 · scripts/recommend-backtest.ts · 2026-07-03 · 2개 컷오프(2026-01·2025-09)로 재현 확인
3~5개현행 공식이 게이트 통과시키는 후보 수 (유니버스 205개 중)
0.3~0.6×현행 공식의 precision@10 (인기순 대비) — 진다
~2배↑개선안(인기 블렌드)의 hit@10 (현행 대비)
한 줄: 순위 로직이 아니라 하드 게이트가 병목. 게이트를 풀고 인기(구매폭) 신호를 섞으면 현행을 크게 이기고 순수 인기순도 따라잡는다.

① 무엇을 어떻게 측정했나

  • 과거 컷오프일 T로 되돌아가 T 이전 출고로만 취향 프로필을 만들고, 현행 scoreRecommendations를 그대로 재사용해 순위 산출.
  • 정답 = 그 거래처가 [T, T+60일]에 처음 산(=T 이전 미구매) 품목 ∩ 재고 유니버스.
  • 지표 = hit@k(상위 k에 정답 1개+ 포함한 거래처 비율)·precision@k·recall@k, 거래처 매크로 평균.
  • 베이스라인 = 인기순(컷오프 이전 구매폭, leakage 제거) · 랜덤(해석적 기대값).
정직한 한계 — ① 구매예측 ≠ 도구의 영업가치(프로모션·영업푸시 등 off-model 요인). ② 재고는 과거 스냅샷이 없어 현재 재고(205개)로 근사 → 절대 recall은 하한, 상대 비교는 유효. ③ v1은 견적학습/전환 레이어 off(as-of-T 재구성 필요). ④ CDV 전용(DL은 glass 별도).

② 핵심 발견 — 하드 게이트가 카탈로그의 97%를 버린다

타입 + 가격±20% + 지역천장 'super'(기본값) 게이트를 통과하는 후보가 거래처당 평균 3~5개뿐. 그래서 top-30을 채우지도 못하고 recall이 구조적으로 ~6%에 묶인다. leakage를 제거한 순수 인기순이 모든 k에서 현행을 이긴다.

④ 해결책 — 전체유니버스 인기 블렌드

게이트를 풀어 후보 풀을 살린 뒤, 개인화 점수와 전사 구매폭 백분위를 섞는다. 게이트 밖 인기 품목은 개인화 0으로 두고 breadth로 끌어올려 인기순의 도달 범위까지 흡수한다.
// 전체 재고 유니버스를 이 점수로 재랭킹 최종 = (1−α)·개인화점수정규화 + α·구매폭백분위 // α = popularityWeight, 권장 0.3~0.5

프로덕션 blendPopularity 함수로 검증한 결과 (승자 행 강조):

전략2026-01 hit@10 / P@10 / R@302025-09 hit@10 / P@10 / R@30
현행공식(기본게이트)17% / 2.4% / 5.9%11% / 1.7% / 3.2%
현행공식(게이트완화)33% / 4.6% / 33%24% / 3.1% / 21%
전체블렌드 α0.3~0.538% / 5.5% / 48%41% / 6.1% / 61%
순수 인기순 (참조)31% / 4.1% / 46%40% / 6.0% / 58%
  • 현행 대비 hit@10 약 2~3배(17%→38%, 11%→41%), recall@30도 6%→48%로 대폭 개선.
  • 순수 인기순도 매 컷오프에서 따라잡거나 넘는다 — 상위는 개인화, 하위는 인기 도달범위를 함께 가져가기 때문.
  • 인기순은 모든 거래처에 같은 리스트라 도구의 존재 이유(취향·산지 적합성)를 버린다. 블렌드는 개인화를 유지한다.

⑤ 프로덕션 반영 (구현 완료 · 기본 off · 가역적)

  • 공용 함수 lib/popularityBlend.ts 신설 — blendPopularity(순수 재랭커) + applyPopularityBlend(getItemPopularity로 breadth 산출). 백테스트가 이 함수를 그대로 호출해 검증.
  • buildCandidates: 신규제안 모드 + popularityWeight>0일 때만 블렌드 적용.
  • 파라미터 popularity_weight(0~1) 라우트에 추가. 기본 0 = 미적용 → 켜기 전엔 현행과 동일(안전).
  • scoring.ts는 미수정. 전 파일 300줄 이하 · lint 통과.
# 켜는 법 (권장 조합) popularity_weight = 0.4 # 인기 블렌드 α geo_ceiling = "any" # 지역 하드게이트 해제(제외 대신 tier 점수로만) price_band = 0.5 # 가격밴드 완화
전부 기존 score_params/RecControls 메커니즘 안. 되돌리기 쉽고 같은 백테스트로 재검증 가능.

⑥ 남은 것 / 다음 스텝

  • α 정밀 튜닝: 분기별 여러 컷오프로 안정성 재확인 후 UI 기본값 확정(현재 0.3~0.5 권장). 스크립트로 바로 가능.
  • 가격 소프트 감점: 현재는 밴드 완화(하드컷 유지). 거리 비례 소프트 감점으로 바꾸면 경계 절벽 제거(선택).
  • v2 백테스트: 견적학습/전환 레이어를 as-of-T로 재구성해 실제 lift 측정(v1은 코어 공식만).
  • Tier 1 폐루프: 추천 시점의 score·params를 recommendations에 박제 → 라이브 성과를 사후에 직접 조인(현재는 실시간 조인이라 복원 불가).
